# Lunar 24 AU / VST3 插件方案

- **第 1 阶段已完成**：Mac 和 Windows 上的 VST3、Mac 上的 AUv2。Mac 上的 Ableton Live 手测通过（MANUAL_TESTS 第 15、17 节，AU 和 VST3 测同一套）。Windows 的独立 App 和插件等业主有了 Windows 电脑和 Windows 版 Ableton Live 后一起手测；在那之前 CI 编出 Windows VST3，并用 Steinberg 的 validator 检查。
- **第 2、3 阶段没有启动。** 第九节是决策资料：列出选项、建议和风险，“建议”不等于决定。

## 一、结论

发声引擎（`core/`）和界面本来就与独立 App 分开，iPlug2 原生支持 VST3 和 AU，所以插件化没有做不到的功能。第 1 阶段真正的工作量在四件独立 App 不需要、插件必须做好的事：`OnReset` 被宿主频繁调用；播放中安全切换整台机器；插件窗口经常关着；只属于独立 App 的功能要拆开。这四件都已做完（第三节）。

| 阶段 | 内容 | 状态 |
|---|---|---|
| **第 1 阶段** | Mac 上 AUv2 + VST3、Windows 上 VST3；乐器类型，立体声 WET 输出；音色随 DAW 工程保存恢复；MIDI 弹奏；窗口可缩放 | 已完成（9 个 PR） |
| **第 2 阶段** | 宿主自动化；跟随 DAW 速度和走带；DRY A/B 单独出轨 | 未启动；三项可以分开决定，见第九节 |
| **第 3 阶段** | 音频输入（PREAMP 处理 DAW 里的声音） | 未启动，按需再评估 |

## 二、已定的决定

| # | 问题 | 决定 | 说明 |
|---|---|---|---|
| 1 | DAW 与格式 | 主力 Ableton Live（Mac 上最新版）；VST3 和 AU 都支持 | AU 做 **AUv2** |
| 2 | 插件里的 MIDI | 插件和独立 App 共用命名方案库（方案里只有绑定）和两个方案切换键；不随 DAW 工程保存（业主，2026-10-10）。插件忽略 CHANNEL（由 DAW 决定）；TRANSPOSE / VELOCITY / SPLIT 存在 `global.bin` 的“(DAW track)”记录里，所有插件实例共用，和 App 各输入设备的记录分开 | 见 DECISIONS “Named MIDI profiles”“MIDI channels in the plugins”“Several MIDI inputs”；第八节 8.7 |
| 3 | 插件里的 REC | **面板保留，点击无效** | 外观和独立 App 相同；录音用 DAW 自己的录音 |
| 4 | 分发 | 不走 App Store / Apple 开发者账号；附说明，用户执行一两条命令 | 只支持 Apple 芯片的 Mac 和 Windows，不做 Intel Mac（第五节） |
| 5 | 播放中切换音色 | **方案 A**：切换瞬间短暂静音 | 见第三节 |

**格式取舍**
- AUv2 是 Mac 桌面上的主流 AU 格式（Logic、Ableton Live 都直接支持），就是放进 `~/Library/Audio/Plug-Ins/Components` 的 `.component` 包，本地签名即可载入。
- **AUv3 不做**（业主，2026-10-08）：它主要为 iPad / iPhone 设计，在 Mac 上也必须装在 App 里、带沙盒和开发者签名。Lunar 24 只做电脑上的 App 和插件。
- **CLAP 不做**：Bitwig、Reaper 能加载这种格式，但 Ableton Live 只加载 VST3 和 AU。

## 三、第 1 阶段怎么做的（已完成）

- **`OnReset` 规则**：DAW 停止走带、旁路、关闭处理时都会调 `OnReset`。插件版只在采样率或块大小真的变了时重建整台机器（`plugin.cpp` 的 `OnReset`，在“停放”音频的情况下重建）；其它情况只放掉按住的音，嗡鸣和效果尾音不受影响。独立 App 的 `OnReset` 照旧完整重建。
- **播放中换整机（方案 A）**：界面线程在后台解码、校验、建好新整机；音频线程在下一个块淡出几毫秒后“停放”（静音、不碰整机）并回应；界面线程换上新整机、释放旧的；音频线程淡入。两条线程只通过原子变量交接，音频线程不等待、不加锁、不分配内存；音频线程没在跑时等待有上限，超时直接切换。DAW 载入工程 / 预置、RESET PANEL（App 和插件都用它）走同一条路。
- **音色存进工程**：`SerializeState` / `UnserializeState`，数据带“格式标记 + 版本 + 分段”头，以后能加段；内容是整机状态，外加 DRONE VOICES 开关（分段 `KEYS`，重开工程时和保存时一样在响；App 每次启动仍是关着）。数据损坏时保持当前音色。App 的状态文件和插件工程数据共用同一个读取函数（`restore_saved_state`），旧格式升级只有一份。插件绝不读 App 的状态文件。
- **窗口关着也能写回**：MIDI CC 带动的旋钮变化、MIDI 绑定触发的卡带和预置切换，在 `OnIdle` 里写回保存状态（不开窗口也有 `OnIdle`）；面板刷新只负责重画。App 一起改，行为不变。
- **插件窗口**：没有金属外壳，面板铺满窗口；拖动窗口或右下角三角都能连续缩放，保持面板比例，限制在半尺寸到原尺寸之间。窗口关了再开，面板自身状态（键盘菜单页、Learn 状态）重置，音色不受影响。
- **App 专用代码隔离**：屏幕尺寸、外壳、音频看门狗、重开音频、录音目录等用 `#if APP_API` 隔开，App 编出来的代码不变；插件专用实现放新文件。插件没有 Preferences；MIDI 端口在 MIDI 面板的 DEVICES 页选，插件的 DEVICES 只有一行“DAW track”。版本号和 Build 号显示在 MIDI 面板右下角。
- **MIDI 方案库共享**：方案（`midi-profiles/`）和 `global.bin` 由 App 和所有插件实例共用；每次修改都在库锁下重读 `global.bin`、只改自己那一项再写回，所以互不覆盖；每个实例约每秒检查一次 `global.bin`，别的实例改了立即采用。
- **REC 不起作用**：`recorderEnabled = false`，REC 和 WET / DRY / ALL 不接收鼠标；`toggleRecording` 在插件里是空函数。
- **输出**：插件声道固定 `"0-2"`（App 仍是 `"0-2 1-2 2-2 0-4 1-4 2-4"`）。引擎按 0 入 2 出准备，这两路是 WET L/R；DRY A/B 照常计算但不送给 DAW。DAW 接上的输出少于 2 路时整块写静音。宿主给的块大于最大块时在插件入口拆开（`processAnyLength`）。
- **日志**：共用 `host/include/host/diag_log.h`，写在设置文件夹的 `logs/`。插件每个 DAW 进程一个会话，按大小分成有限的几个文件，文件名前缀 `vst3-` / `au-`，实例在行里用 `#n` 区分。
- **一份代码两种格式**：VST3 和 AUv2 编的是同一份 `plugin.cpp` / `plugin.h`，声音、面板、MIDI、工程数据格式只有一套。唯一的格式分支：状态块读坏时，AU 返回 0（它的包装层把 0 当成“没恢复”），VST3 返回已读的字节数（后面紧跟宿主自己的 bypass 标志）。
- **构建**：VST3 / AUv2 目标只在 macOS / Windows 上加；Linux 只编引擎和测试。VST3 SDK 固定 `v3.8.1_build_84`（MIT 许可，CI 下载，不进仓库）。AU 类型 `aumu`、子类型 `Lu24`、厂商 `Lua2`；VST3 分类 `Instrument|Synth`。
- **电脑键盘**：Ableton 会拿走按键，插件窗口里用 A W S E D… 弹不可靠；插件里弹奏走 DAW 的 MIDI 轨（Ableton 的电脑 MIDI 键盘按 M 开启）。这是预期行为。

PR：#124（方案）、#125–#130（OnIdle 写回、安全切换、拆分与构建、`OnReset`、工程状态、窗口）、#131（CI 验证）、#132（手测）。

## 五、分发

- **macOS（不用开发者账号）**：CI 给插件做本地签名（`codesign --sign -`，Apple 芯片要求至少有本地签名）。用户把 VST3 放进 `~/Library/Audio/Plug-Ins/VST3/`、AU 放进 `~/Library/Audio/Plug-Ins/Components/`；网上下载的文件执行 `xattr -dr com.apple.quarantine <插件路径>` 解除隔离；AU 新装后 DAW 没看到就执行 `killall -9 AudioComponentRegistrar` 或重新登录。DAW 要以原生模式运行，不能用 Rosetta。
- **Windows**：把 `Lunar24.vst3` 文件夹放进 `C:\Program Files\Common Files\VST3\`，不签名也能载入。
- CI 产物：`Lunar24-Plugins-macOS`、`Lunar24-Plugins-Windows`。
- **商标**：只写“VST3 格式”，不使用 VST 标志。
- **多实例**：每个实例从同一个固定种子开始，同样音色的两个实例漂移完全一样；要不要每实例不同种子，业主听了再定。

## 八、当前能力与边界

### 8.1 结论

第 1 阶段已经可以在 DAW 里演奏，并把当场的声音实时录成音频；只录 MIDI、之后让 DAW 完整重演所有面板操作，现在还做不到（8.5、8.6）。对 ambient / drone 以音频为主要成果的用法，不需要等第 2 阶段。

### 8.2 能做什么、边界在哪

| 场景 | 现状 | 边界 |
|---|---|---|
| 在 Ableton 加载 AU / VST3 | Mac 已验收 | Windows 待业主手测；其它 DAW 未测 |
| MIDI 键盘、Ableton 电脑 MIDI 键盘演奏 | Mac 已验收 | DAW 负责 MIDI 输入和监听 |
| 鼠标操作面板、DRONE、光敏头 | 可以 | 声音能录下来，操作本身不会变成 DAW 自动化 |
| 录 MIDI 再回放 | 代码路径具备 | 没有单独验收这条流程（8.10） |
| 把插件声音实时录成音频 | 可以 | 在 DAW 里录；面板 REC 不工作 |
| 插件后面加 EQ、压缩、混响 | 可以 | DAW 处理的是立体声 WET |
| 多实例 | Mac 双实例已验收 | 各实例的声音互相独立；MIDI 方案库、切换键和“(DAW track)”设置由所有实例和 App 共用 |
| 存工程后恢复音色、接线、键盘设置、DRONE 开关 | Mac 已验收 | 不保存整场演奏过程，也不保存振荡器相位、延迟缓存这类瞬时状态 |
| 存 / 调宿主预置，播放中切换 | Mac 已验收 | 短暂淡出 → 切换 → 淡入，旧尾音不保留 |
| 关窗后 MIDI 改值并保存 | Mac 已验收 | 刚改完立刻保存的时序边界值得补查（8.10） |
| 离线导出、冻结 / 转音频 | 引擎能拆块处理 | 没有原生 DAW 验收；尾音长度报告为 0（8.8） |
| DRY A/B 单独出轨 | 没有 | 只有 WET 立体声，正常演奏、录音、混音不受影响（9.9） |
| 外部音频输入 | 没有 | 扩展的是效果器用途，合成器本身不需要（9.10） |
| MPE、内部琶音的 MIDI 输出 | 没有 | 要导出内部琶音的 MIDI 时才是必需 |
| 插件内部录音 | 没有 | 既定选择，用 DAW 录 |

### 8.3 实时录成音频

Live 里：Lunar 24 放在 MIDI 轨；新建音频轨，`Audio From` 选 Lunar 所在轨（`Post FX` 会带上它后面的效果），监听设 `Off`，开录，结尾留够尾音再停。录下的是表演结果：所有可听的变化都在，但之后不能单独改“第 12 秒滤波转了多少”，只能重录或处理音频。参见 [Ableton：Recording MIDI as Audio](https://www.ableton.com/en/live-manual/12/routing-and-i-o/#recording-midi-as-audio)。

### 8.4 录 MIDI 再回放

DAW 回放的音符和实时演奏走同一个入口（`ProcessMidiMsg()`），按块内位置换算成引擎的采样时间，所以普通音符跟着 DAW 时间线走，不需要第 2 阶段的时钟同步（那是给插件内部 ARP / SEQ 用的）。

| 操作 | 能留下什么 |
|---|---|
| 外部键盘、Ableton 电脑 MIDI 键盘的音符 | 录进 MIDI 片段，可以编辑 |
| 控制器发来的 CC、弯音 | DAW 能录；能否按原样重现取决于绑定、起始状态和消息是否真的进了轨道 |
| 鼠标拧旋钮、点 DRONE、拖接线、光敏头 | 不会成为自动化；只能录音频 |
| 鼠标点插件琴键、插件自己的电脑键盘 | 直接进引擎，插件没有 MIDI 输出（`PLUG_DOES_MIDI_OUT 0`），DAW 录不到 |
| 插件内部琶音器 / 音序器生成的音 | 同上，录不成 MIDI |

满意的表演同时录一条音频，最不容易丢。

### 8.5 没有宿主自动化

例如 8 小节里用鼠标把滤波从暗转亮：工程只保存旋钮的最后位置，回放不会重演这个变化。现在能用的是 DAW 自己的音量 / 声像 / 发送自动化、插件后面效果器的自动化，以及剪辑已录音频。MIDI Learn 不能完全替代：消息必须真正进入轨道（MPK 的 PLUGIN / DAW 模式下部分旋钮被 Ableton 脚本拿走，见 MANUAL_TESTS 第 17 节）；相对旋钮和“按一次翻转”的绑定还依赖起始状态，从不同状态回放结果不同。

### 8.6 内部 ARP / SEQ 不跟 DAW

内部琶音器 / 音序器没有和宿主时间线同步，两边 BPM 设成一样也不保证同拍起、跳转后对齐。自由演奏和持续音不受影响；要和鼓点严格锁定时是明显限制。绕开办法：用 DAW 的 MIDI 片段或 DAW 自己的琶音器排节奏，送进 Lunar 的普通键盘模式。DRONE 在 DAW 停止后继续响是既定行为（T17.3）。

### 8.7 MIDI 方案属于使用者，不属于工程

- 命名方案（`midi-profiles/`）只保存绑定，App 和插件共用；两个方案切换键是全局的。
- CHANNEL / TRANSPOSE / VELOCITY / SPLIT 按输入设备存在 `global.bin`。插件只有一行“DAW track”，忽略 CHANNEL（由 DAW 决定），TRANSPOSE / VELOCITY / SPLIT 存在自己的“(DAW track)”记录里，所有插件实例共用，和 App 的设备记录分开。
- 每个实例各自切换方案。DAW 工程只恢复机器状态和 DRONE 开关，不含任何 MIDI 设置（业主，2026-10-10）。所以同一个 MIDI 片段的音高、力度、分区由当前方案和“(DAW track)”设置解释；要一样的演奏方式，就选同样的方案和设置。

### 8.8 尾音长度报告为 0

`host/` 里没有调用 `SetTailSize`，iPlug2 默认的 `mTailSize` 是 0，VST3 的 `getTailSamples()` 和 AU 的 `kAudioUnitProperty_TailTime` 就把 0 报给宿主——而插件实际有包络释放、混响和延迟。宿主可能据此在离线导出或冻结时截掉尾音（[Steinberg 说明](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/classSteinberg_1_1Vst_1_1IAudioProcessor.html)）。还没确认 Ableton 是否真的截尾；先实测，再决定报多长（持续 DRONE 与有限尾音的处理不同）。这是第 1 阶段的小修补，不需要启动第 2 阶段。

### 8.9 和一般合成器插件比

成熟的合成器插件通常有常用参数的宿主自动化，有节奏功能时还跟 DAW 同步（如 [Diva](https://u-he.com/downloads/manuals/plugins/diva/Diva-user-guide.pdf)、[Surge XT](https://surge-synthesizer.github.io/manual-xt/)），但多输出、音频输入要看用途；“别人都有”不等于 Lunar 现在必须做。

### 8.10 建议补的检查（未执行）

| 检查 | 做什么 | 要确认 |
|---|---|---|
| MIDI 录制与回放 | 固定音色录一段普通键盘演奏（长短音、弯音；不要求踏板），存工程重开再回放 | 音符和表情正常，无漏音 / 挂音；记下当时的 MIDI 方案和“(DAW track)”设置 |
| 实时录音频 | 录一段含 DRONE、鼠标旋钮、光敏头和效果尾音的表演，关掉插件只听录音 | 当场的变化都在音频里 |
| 导出和冻结 / 转音频 | 听开头、最后一个音和混响尾部；覆盖 MIDI 驱动的声音和持续 DRONE | 无空白、漏音或截断；核实尾音报告的影响（8.8） |
| 工程重现边界 | 换 MIDI 方案后回放旧工程；控制器改值后保存重开，包括刚改完立刻保存 | 分清工程里存的状态、全局设置和保存时序；有问题单独修 |

## 九、第二、第三阶段的分析与待决策

这一节是决策资料，没有启动实施。自动化、DAW 同步、DRY 多输出、音频输入四项可以分别决定，也可以都不做；下面“必须处理”的要求只在采用对应功能时才适用。核查基线：iPlug2 `d54f6905`。

### 9.1 自动化是什么、值不值得

通俗地说：让 DAW 不只记住弹了哪些音，还记住“什么时候把哪个旋钮转到哪里”，按时间线重放，并能直接修改这条曲线（例如 8 小节从闷到亮、最后两小节加大混响）。机制包括稳定的宿主参数编号、范围和曲线、面板操作的开始 / 变化 / 结束通知，以及 DAW 回放到引擎和面板的反向同步。

| 概念 | 记录的是什么 | 现状 |
|---|---|---|
| 工程音色保存 | 当前机器配置的快照 | 已有 |
| MIDI 音符 | 音高、按下 / 松开时机、表情 | 已有 |
| 插件内部 MIDI Learn | 把进来的 CC / 音符映射到控制 | 已有；依赖绑定、起始状态和消息进入轨道 |
| 宿主参数自动化 | DAW 时间线上的插件参数值 | 没有 |
| 轨道音量 / 声像 / 后接效果器自动化 | DAW 或后接设备的参数 | 现在就能用 |
| 实时录音频 | 当时实际的声音 | 已有 |

以即兴、声音探索、录音频为主时可以推迟；经常反复编排音色运动时收益很大。做自动化也不等于一次开放全部参数、所有程序切换和完整采样级曲线：范围和精度可以分开选，较小但可靠的参数集合也是可以长期成立的产品范围。

### 9.2 iPlug2 版本与维护

| 路径 | 短期 | 中期 | 建议 |
|---|---|---|---|
| 继续锁定当前提交 | 保持已验收的 App / 插件基线 | 长期完全不维护会积累差异 | 现在合理，不是永久冻结 |
| 为具体需求加小范围框架补丁 | 能解决明确瓶颈，要做实时 / 跨格式检查 | 每次升级要判断补丁能否删除或重新适配；争取上游接纳 | 创作需求和精度目标定了再用 |
| 将来整体升级到有明确收益的提交 | 拿到上游修复或系统兼容；回归面较广 | 少积累旧接口和本地补丁 | 单独 PR，写清收益和回归范围 |
| 自动追 master 或用旧实验分支（如 2021 年的 `VST3/paramqueue`） | 没有已证明的收益 | 发布难复现 | 不建议 |

iPlug2 子模块锁定在 `d54f6905`（2026-10-08 时与上游 master 相同，所以下面的自动化精度限制不是“项目落后”造成的），VST3 SDK 固定 `v3.8.1_build_84`。独立 App 用自己的 `iPlug_app_override.cpp` / `iPlug_app_host_override.cpp` 替换上游的 `IPlugAPP.cpp` / `IPlugAPP_host.cpp`（`host/CMakeLists.txt` 约 72–80 行），后者有大量设备、MIDI、存档定制；CMake 门禁只检查用的是替换文件，不检查和上游的差异，文件注释里提到的 `tools/check_host_override_drift.py` 已经删除。升级各自单独成 PR，不自动追 master，也不永久冻结。

### 9.3 自动化：范围与编号

从面板布局（`build_panel_layout()`，不含菜单）数出 **195 个参数**：116 旋钮、61 按钮、16 拨杆、摇杆 X/Y。按模块：经典 DRONE 80，DRONE 3/6 共 24，VCO A/B 16，VCF 11，包络 A/B 12，LFO A/B 6，摇杆及偏移 4，PREAMP 1，包络跟随器 2，五步音序器 12，混音器 20，效果器 7。`sequencer.clock`、`effector.phone` 没有面板控件，不开放；键盘菜单和效果器程序内部参数也不开放。DRONE VOICES 六键、总 MUTE、四个光敏头、触摸键盘、接线、REC、RESET PANEL 都不是普通参数，不能机械注册。

**编号**：注册表有 349 个参数，最大 ID 415，不连续；iPlug2 的 VST3 和 AU 都把连续的参数序号直接当宿主 ID。建议把原来的“宿主 ID = 内部 ID”改成：在 spec 里显式定义永久不变、连续的 `host_id`，生成器产出它和内部 ID 的双向映射；发布后只追加，不因布局、模块顺序或名称改变而重排，不动机器存档 ID。乐器自己还没有任何宿主参数，所以这份契约现在就能定。VST3 版为了收 16 个通道的 MIDI，iPlug2 已注册 2080 个隐藏、不可自动化的 MIDI CC 代理参数，ID 从 65538 起（`host/CMakeLists.txt` 的 `VST3_NUM_MIDI_IN_CHANS=16`），所以 `host_id` 要保持在 65538 以下。若坚持两套数字相同，就要做 AU / VST3 的稀疏 ID 适配；不要用几百个空参数占位。参数名带模块前缀（“VCO A Tune”）；枚举用真实档位文字；归一化沿用 `knob_to_value` / `value_to_knob`，保留原有 DSP 平滑。发布后的兼容契约包括 ID、范围、档位、单位和归一化曲线。

**范围选项（待决定）**：
- 195 个现有面板参数；
- 195 + DRONE 六键 = 201（曾被推荐：DRONE 开关有编排价值；六键要另定状态、保存和同步）；
- 再加总 MUTE / 四个光敏头（牵涉 App 里“MUTE 不保存、光敏手势不保存”的语义）；
- 只开放实际常用的一小组（清单未定；201 不是最低要求）。

### 9.4 自动化的六项正确性要求（采用才适用）

1. **分清回调线程和来源**：`postParameter()` 改 UI 拥有的保存状态并写单生产者队列，不能从任意 `OnParamChange()` 调；该回调可能在音频线程上，`kHost` 只说明来源。要分清 UI 手势、处理期宿主事件、非处理期更新，交给所有权明确的桥接层。
2. **保留时间位置**：`parameterFromAudioThread()` 没有 sample offset，事件排在块起点；要复用运行时已有的绝对采样时间 `EventTimebase`。
3. **容量**：`EventTimebase` 连续事件容量 64，满时只能合并同参数事件；`sendParameterFromAudioThread_()` 不检查入队结果，之后仍可能回写保存值。195 个参数批量初始化不能逐个塞进去；要有界的交付和容量策略，保住音符事件的容量。
4. **音频到 UI 的同步与保存**：`fromAudioQueue_` 只有 256 项，还承载 MIDI 改值、动作和旧接线计划的回收。连续参数改用带版本 / 来源的最新值同步；保存工程时要拿到一致的最新状态，不能只等下次 `OnIdle`，也不能在保存回调里随意并发消费 UI 队列。
5. **各处一致**：整机恢复、RESET PANEL、MIDI Learn、面板和自动化要同步同一份值；VST3 控制器有参数副本，恢复后也要同步。初始化 / 恢复不是用户手势，不能变成 `performEdit`，不能用参数默认值盖掉刚读入的旧工程；切换前排队的旧自动化不能盖掉新机器。
6. **控件手势**：自绘 `IControl` 没绑宿主参数。拖动、滚轮、双击复位、按钮 / 拨杆、摇杆两轴都要接开始 / 变化 / 结束；关窗、失焦时收尾。宿主回放只更新显示和声音，不算新的手动编辑；MIDI 改值要和接管 / 相对旋钮的基准同步。

| 要求 | 主要修改面 | 对 App / 声音的潜在影响 | 相对风险 |
|---|---|---|---|
| 1 线程与来源 | 插件参数桥、共用引擎入口、队列所有权 | 多生产者误用单生产者队列 → 状态竞争 | 中高 |
| 2 时间位置 | 宿主事件入口、采样时间调度 | 参数生效时刻变化 | 中 |
| 3 容量 | `EventTimebase`、批量初始化 | 丢参数 → 保存值、界面、声音不一致；挤占音符 | 中高 |
| 4 同步与保存 | 共用 `fromAudioQueue_`、`OnIdle` / `SerializeState` | 影响 App 的 MIDI 和接线回收 | 中高 |
| 5 一致性 | 插件 `IParam`、VST3 控制器缓存、整机切换 | 旧工程被默认值覆盖；回放反写成循环 | 中高 |
| 6 手势 | 共用 `panel_editor` 自绘控件 | App 鼠标 / 滚轮 / 摇杆操作可能回归 | 低至中 |

这些都不用重写振荡器、滤波器、效果算法，但第 1–5 项触及共用的实时路径，控制顺序或丢事件同样会改变听到的声音，必须回归 App 的 MIDI、状态、接线和演奏。

**MIDI Learn 要不要写宿主自动化（待决定）**：
- 不写（曾建议）：面板操作录成宿主自动化；插件 Learn 继续控制声音并同步参数值，但不额外写自动化。控制器数据照样能录成 DAW 的 MIDI 片段，或用 DAW 自己的参数映射录自动化。
- 写：要补非音频线程的宿主通知、无鼠标时的手势结束规则，并防止 MIDI 回放又被写成自动化。
- 无论哪种，宿主曲线回放都不能反过来制造新的编辑手势。

### 9.5 自动化精度（包装层限制）

锁定的 iPlug2 里，VST3 的 `ProcessParameterChanges()` 只读每个参数队列的最后一点（带 offset），其余点丢失；AU 的 `DoScheduleParameters()` 只处理 immediate 事件，不处理 ramp。以 48 kHz、512 样本块为例，一块约 10.7 ms：这意味着控制曲线在这个量级上被简化，**不是**声音每 10.7 ms 断一次；慢扫滤波和快速密集的节奏变化受影响不同，要听 / 渲染比较才知道够不够。

**选项（待决定）**：
- 暂不做自动化：不为没采用的功能改框架。
- 先做精度边界明确的自动化：改动少，但不能宣称完整的块内曲线。
- 需要完整点 / 斜坡时，补小范围包装层适配（AU / VST3 都要），接到有界的实时调度；仍保留原有 DSP 平滑。要用同一曲线在不同块大小下比较，并在 macOS / Windows 原生构建里检查；validator / auval 通过代替不了这项检查。

### 9.6 效果器程序

面板的 1–2–3 拨杆先调 `loadSlotCartridge()` 再改选择参数；卡槽里挑的候选卡带（`slotCartridge_`）只是 UI 暂存值，工程存的是左右实际加载的卡带。所以只录 0/1/2 不能复现换卡带：左侧原是卡带 A 程序 2，后来换成卡带 B 程序 2，宿主只记“2”就分不清。`syncParametersFromAudioThread()` 还会为这两个参数触发卡带加载，不能不分来源地复用。

| 选项（待决定） | 收益 | 限制与长期代价 |
|---|---|---|
| 左右各一个 39 档“卡带 + 程序”参数（13 卡带 × 3 程序；曾建议），面板不变 | 能明确重演用了哪张卡带的哪个程序 | 卡带和档位要作为一次变化一致交付；已发布的程序身份和归一化映射要冻结 |
| 只自动化当前已加载卡带内的 1 / 2 / 3 | 范围小，适合固定卡带的工程 | 不含换卡带；同样档位取决于已加载卡带 |
| 暂不自动化程序，只开放 X / Y / Z、BLEND、MASTER 等 | 避开复合状态，保留常用渐变 | 切程序只能现场操作或录音频 |

不管选哪种，App 的“选候选卡带 → 拨杆加载并选程序”操作、左右独立效果、约 15 ms 淡出 / 重置 / 淡入都不变。以后若从 39 档扩到 42 档，不能直接扩大范围，否则旧工程的归一化值会指向别的程序。

### 9.7 DAW 时钟与走带

现有 `ControlEventKind::clock` 只驱动键盘琶音器和 16 步音序器（一拍 4 步，SINGLE / TWIN / SPLIT 共用）；五步音序器、LFO、DRONE、效果延迟不跟它，扩展同步要另列范围。

采用时要补的：
- **时钟归属明确**：不能等第一拍到了才停内部时钟，也不能让菜单 BPM 或 CLOCK 插孔抢回控制；HOST 下忽略 MIDI 时钟；插件 CLOCK / RESET 插孔在 HOST 下怎么处理要写明（建议都归宿主）。App 行为不变。
- **从 PPQ（以四分音符计的播放位置）算块内时钟位置**：处理块边界、舍入、变速、循环、跳转、负位置 / 预滚、离线渲染；不用 UI 定时器或墙上时间。iPlug2 的时间信息有默认 / 无效值，AU / VST3 包装层没有完整保留有效性，不能把缺失信息当成 120 BPM。
- **开 / 关门**：`externalClockPulse_()` 用相邻脉冲间隔推算关门时间，第一拍没有间隔，暂停后可能读到旧间隔；HOST 下要明确生成开关门或提供周期，停止时放掉琶音 / 音序的音并清理相位历史。
- **重启不丢和弦**：不能用整机重建处理播放 / 停止；`ControlEventKind::sync` 经 `releaseRun_()` 调 `reset()` 会清掉和弦；`restartPattern()` 能保留和弦，但不负责关门和按样本定位，要组合成明确的走带接口。
- **区分 Reset 来源**：插件 `OnReset` 现在会请求全体键盘 gates reset；走带变化、DAW Reset、旁路、采样率重建要分开。

**产品规则（待决定）**：
1. **时钟模式**：插件始终跟 DAW（HOST）——旧工程的琶音 / 音序行为会随升级改变；或每实例 HOST / INTERNAL（曾建议）——新实例默认 HOST，第 1 阶段旧工程没有这个字段时用 INTERNAL（保留原来的 MIDI / CLOCK 接管能力），设置存在插件工程数据的可选分段里，不写 App 全局文件。
2. **开始 / 跳转 / 循环**：从下一个十六分音符网格重新从第 1 步开始（曾建议，范围明确）；或追赶绝对乐句位置（算出“从头一直放到现在应在哪一步”，涉及长度、方向、随机步、RHYTHM、和弦历史）。停止时停止自动步进并关掉生成的音，DRONE 和效果尾音不静音，普通 MIDI 演奏照常；拍号变化是否影响对齐要随规则一起定。

| 补齐项 | 影响面 | 要保护的行为 |
|---|---|---|
| HOST / INTERNAL 归属 | 实例设置、共用键盘时钟模式 | App 原有接管规则；HOST 下不被内部 BPM 或插孔抢回 |
| PPQ → 块内事件 | 插件时间桥、框架有效性、事件时间 | 实时和离线都按音频时间推进 |
| 开 / 关门与停止 | 共用 gates、外部时钟相位历史 | 不全局关 DRONE / 效果尾音 |
| 保和弦重启 | `ArpSeq` restart / reset | 不意外清空按住的和弦 |
| 循环、跳转、继续 | 走带检测、序列位置 | 选定的位置策略，不暗中混用 |
| Reset、旁路、采样率重建 | 插件生命周期、`notesOffRequested_` | 新的停止策略不被原复位路径覆盖 |

这是后续功能里最集中改变演奏行为的一项（错误会表现为起拍不齐、重复 / 漏步、挂音、和弦丢失）。主要录自由演奏时可以延期；DAW MIDI 音符的时机不依赖它。

### 9.8 DRY 辅助输出

现有 DRY A/B 是 **VCO A/B + SUB 经各自 VCA 后**的信号，在混音器、滤波、失真、效果和 MASTER 之前；不是六个 DRONE 的分轨，也不是全机干声。引擎（`RuntimeOutput` / `DeviceAdapter`）本来就算出 WET L/R、DRY A/B 四路，第 1 阶段只交出前两路，所以这项是把已有结果接到宿主总线，不加 DSP、不重调电平和 MUTE / 淡出。

**拓扑选项（待决定）**：
- 延期：只有 WET。
- WET 一组立体声主总线 + DRY 一组立体声辅助总线（左 A、右 B）（曾建议）。iPlug2 写 `0-2.2`；`0-4` 是一组四声道（VST3 默认甚至映射成 Ambisonics），不能混用。要兼容只用 WET 的宿主配置。
- DRY A、B 两个真正的单声道总线：要额外处理 AU 的“每总线 2 声道”假设，暂不建议。

建议引擎固定 0 入 4 出，只把已启用的输出接给宿主，其余写进预分配缓冲；总线开关不重建机器（iPlug2 的 VST3 `ProcessAudio()` 和 AU 渲染都会按块更新连接，不一定先调 `OnReset`），这样尾音、相位、演奏状态都不会重启。App 的声卡协商和 2 / 4 输出选择不用改。

| 工作 | 修改面 | 主要风险 |
|---|---|---|
| 声明 WET 主总线 + DRY 辅助总线 | 插件 config、AU / VST3 适配 | 误写成单组四声道；旧工程主输出拓扑 |
| 连接与预分配缓冲 | `ProcessBlock`（现在“连接不足就全静音”、按 `NOutChansConnected()` 遍历要改成按具体总线检查）、32 / 64 位路径 | 写进空缓冲；只启用 DRY 时误静音；假设连接连续 |
| AU 多总线拉取 | AU 包装层 | 同一时间片推进引擎两次 |
| 保持运行时与 App 行为 | 插件准备策略 | 总线切换意外重建；改共用适配器影响 App |

这是中等范围的宿主集成，不是声音算法重写，也不是把 2 改成 4 就完事。不需要把 VCO A/B 单独做外部处理时可以延期。

### 9.9 第三阶段：外部音频输入

插件现在声明 0 输入；这项让 DAW 里的声音进入 PREAMP / 内部处理，扩展的是效果器用途，不是演奏和录音的前提。原设想是 AU music effect 类型 / VST3 侧链，初估 1–3 个 PR，但还没做格式、宿主和状态兼容核查。启动前要定：喂给哪些输入、单 / 双声道怎么解释、是否同时保留 MIDI 演奏、宿主怎么路由、无输入时怎么办、会不会改变现有插件身份（不能悄悄替换已有插件）。App 的输入设备选择和 PREAMP 行为保持不变。

### 9.10 保护独立 App：整体风险

| 领域 | 改声音算法？ | 可能影响 App 的地方 | 风险 |
|---|---|---|---|
| 完整效果程序参数 | 不需要 | 共用卡带 / 档位动作及回写 | 中；保持切换包络和面板 |
| DAW 同步 | 不改振荡器 / 效果；改演奏状态机 | 共用键盘时钟、ARP / SEQ、gates、reset | 行为风险集中；显式模式，App 和旧工程保持旧语义 |
| DRY 多输出 | 不需要 | 若改共用适配器，影响设备输出 | 中；插件总线独立适配 |
| 整体 iPlug2 升级 | 不直接改 core | App 的替换文件、平台构建、窗口、音频 / MIDI 生命周期 | 回归面广；单独评估 |
| 音频输入 | 原有输入 DSP 可复用 | 共用输入适配与路由 | 待核查，不先承诺低风险 |

（自动化各项见 9.4 的表。）core 保持不依赖框架，音频线程不分配、不等待、不加锁。但 host / core 的目录边界不等于风险隔离：共享队列、控制时机、保存规则只改在 host 也能改变声音。最终按具体 diff、针对性测试和 App 听音回归判断。参数 ID / 范围 / 归一化、插件身份、旧工程缺字段时的行为是长期契约，要在相应能力第一次发布前定清楚。
