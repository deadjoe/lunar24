## 0. The production delta, in full

ONE function, plus the helpers it needs and the comment that documents them —
`core/include/lunar24/core/vco.h`. Code-only diff against `ab8bf99a`:

```cpp
// in Vco::emittedAt_(double cp, double step), after the triangle-BLAMP and pulse-BLEP terms:
const double sw = sawBlepWeight_();
const double iw = invSawBlepWeight_();
if (sw > 0.0 || iw > 0.0) {
  const double r = sawJumpResidual_(cp, step);
  if (sw > 0.0) v -= sw * r;   // the saw's jump is DOWNWARD (-2) -> subtract R
  if (iw > 0.0) v += iw * r;   // the invSaw's is UPWARD (+2) -> add R
}

static double sawJumpResidual_(double cp, double step) {
  const double dt = std::fabs(step);                  // |instHz| / sr; finite on reversal.
  if (!(dt > 0.0) || !std::isfinite(dt)) return 0.0;  // zero/NaN step -> no correction.
  const double w = (dt < kPolyblepMaxDt) ? dt : kPolyblepMaxDt;
  return polyblepResidual(frac(cp), w);
}

double sawBlepWeight_() const {      // 0.0 on every waveform except kMorphRing
  switch (wave_) {
    case VcoWaveform::kMorphRing: return wave_map::sawWeight(wave_map::kRingEqual, morph_);
    default: return 0.0;
  }
}
double invSawBlepWeight_() const { /* the same, wave_map::invSawWeight */ }
```

plus `core/include/lunar24/core/vco_wave_map.h`, where the per-node weights and the identity that
justifies scaling by them are written out. The three load-bearing structure points:

* the correction is **scaled by the node's own weight**, so it vanishes with the node it belongs to;
* the **outer guard** `if (sw > 0.0 || iw > 0.0)` is what makes the default patch bit-identical — at
  `morph_ = 0.5` (the sine node) BOTH weights are exactly `0.0`, so nothing is computed at all;
* **no hidden switch**: no `#ifdef`, no runtime flag, no build option. The neutralised arm B exists
  only as a **generated shadow include root** on a separate compile line (see §3).

`sawJumpResidual_` reads `polyblepResidual` **directly** from `polyblep_kernel.h` (the S3 kernel
family), and the width is capped at `kPolyblepMaxDt` in the same way S3's pulse kernel caps it.

## 2. The fourth compiler/platform pit: `std::sin` differs by 1 ULP across platforms

The three pits already on record for this project are MSVC-vs-clang language/format issues
(`C4996`, `C3493`, `C4723`). This one is a different kind: **the standard library's numerics are not
the same function on different platforms**, and it silently changes a bit-exact criterion.

**How it was found.** `sine_node_bit_diff_count` compared the candidate's 8 sine windows against the
committed baseline windows, frame by frame, and read **0** on this machine (macOS / Apple libm) and
**652** in CI (glibc). 652 frames is not noise and not a rounding wobble in the correction — the
correction is provably inert at `morph = 0.5` (§3). The default patch evaluates
`std::sin(kTwoPi * p)` (`core/include/lunar24/core/vco.h:508`), so both sides go through libm.

**The measurement, not the inference.** Feeding 200 000 *identical* arguments to `std::sin` on the
two toolchains: they disagree on **3.76 %** of them, and every single difference is exactly **1 ULP**.
Rendered through the product, the default path differs on **3.64–3.98 %** of frames, all exactly
1 ULP. Then the decisive control: a **literal pre-S6 tree** (no correction code at all) rendered by
the **CI** compiler reproduced the **same 652** differing frames. So the 652 was not caused by the
change — the baseline was simply not reproducible by the compiler under test:

> A criterion whose baseline cannot be reproduced bit-for-bit by the compiler under test is
> measuring the compiler.

**The reproduction recipe**, kept because a future slice will hit this again:

```
docker run --rm --platform linux/amd64 -v /tmp/x:/w -w /w gcc:13   # MUST be amd64
```

`--platform linux/amd64` is load-bearing: on arm64 the same source produces *different* results,
because the arm64 build contracts `a*b+c` into an FMA where the x86 build does not — i.e. on arm64
the experiment would have reproduced the *host*, not the CI, and would have "confirmed" the wrong
hypothesis. The host's own binary was never the reference; the CI compiler was.

**Consequence, and why the fix is not a loosened threshold.** Widening
`sine_node_bit_diff_count` to "a few hundred" would have made the criterion accept precisely the
platform difference it was supposed to exclude, and would have gone on reading 0 locally — a
permanent blind spot with a green light on it. The fix removes the platform from the comparison
instead: arm B is built **by the same compiler, from the same sources, with the same flags, in the
same CMake configuration**, so no libm can move it relative to arm A.

## 3. The A/B criterion: arm B, and the two ways it could degenerate

### 3.1 How arm B is produced

`tools/stage_gh19_s6_shadow.py` is the **single source** of the neutralisation edit, shared by CMake
and by the mutant runner. It reads the tree's own `core/include/lunar24/core/vco.h`, replaces the
two application lines with a comment block plus `(void)r;`, and writes the result into a **shadow
include root** that is placed **FIRST** on the compile line of a second executable
(`gh19_s6_saw_probe_neutral`). Every other header still resolves from `core/include`.

"Same build" is **checked, not asserted**. CMake records both compile lines in its generated
per-target `flags.make`, and the two differ in exactly one token — the shadow root, first, on arm B:

```
arm A  -I<t>/tests/host -I<t>/core/include -I<t>/generated -I<t>/host/include
arm B  -I<build>/gh19_s6_shadow -I<t>/tests/host -I<t>/core/include -I<t>/generated -I<t>/host/include
CXX_FLAGS  -O3 -DNDEBUG -std=c++17 -arch arm64 -Wall -Wextra -Wpedantic -Werror   (both)
CXX_DEFINES  (empty, both)          link line: identical but for the object and -o name
```

The arm-B target's `target_link_libraries` is written to be character-for-character the arm A line
for the same reason: a second difference in the build description is one a reviewer would have to
rule out, and there is no reason to ask them to.

Two alternatives were rejected, and the reasons are load-bearing:

* **a committed copy of the corrected header** would be a second encoding of the same code, free to
  drift from the product; the A/B would then be comparing the product against a stale artefact;
* **an `#ifdef` in `vco.h`** would put a build-time configuration branch into the shipped DSP,
  which is exactly the "no hidden switches" hard edge S0 carries.

The edit keeps the **outer guard** and the **residual call** and only stops the correction from
reaching the output (`(void)r;`). So the two arms differ in **one thing only**: whether the value-jump
correction reaches `v`. If they also differed in whether the residual is computed, a difference at
the sine node could be explained by the call itself rather than by the term — a weaker claim.

### 3.2 The two refusals that keep the A/B from being vacuous

An A/B that silently compares A against A would **pass while measuring nothing** — the degenerate
identity this project has already been bitten by. Two `NEUTRAL-ARM` **refusals** (exit 4, no
judgement) block it:

* the two arms' `gh19_s6_plan.tsv` must be **byte-identical** — the same scenario list, so the
  compared windows correspond;
* at **morph 0.0** (the saw node, where the correction IS in force) the two arms must **differ**. If
  all witness windows are byte-identical, arm B is arm A and the criterion would be comparing the
  product against itself.

A refusal, not a failure, on purpose: it says *this run cannot judge*, which is a statement about the
run, not about the product.

### 3.3 Why `sine-node-leak` is still the right mutant

`sine-node-leak` adds a `1e-9` floor where the saw weight is 0 — invisible to every dB criterion in
the file, visible bit-for-bit. Under the A/B it fires `EQUALITY-SINE` because the leak is in arm A
and absent from arm B — which is the honest reason: the criterion is asking "is the guard inert on
the default patch", and a `1e-9` leak answers no.

## 4. The wiring check: what it adds that the numeric criteria cannot

The numeric criteria are all **measurements**, and every measurement has a blind spot. The
correction could be wired to a *third* caller, or its weights could be read by a path the probe does
not exercise, and every measured column would stay exactly where it is. The ruling asked for a
grep-level check, and this is the shape it took:

* **A declared counts table.** 12 `wiring` rows in `acceptance_criteria.tsv`, each
  `(file, symbol, expected code-hit count)` for the six symbols named in the ruling. The gate rescans
  `core/`, `host/`, `generated/` and FAILS `S6-WIRING` if any (file, symbol) count differs, if a
  declared file is absent (REFUSE `WIRING-SOURCE`), if the same (file, symbol) is declared twice, or
  if one of the six symbols has **no hit at all** (a renamed symbol must not silently drop out of
  the check, which is why all six must be declared).
* **Three structural anchors**, because a counts table alone is satisfiable by moving code around:
  1. the guard anchor `if (sw > 0.0 || iw > 0.0) {` occurs **exactly once** in the tree;
  2. the guard **region** reads the three corrected names (`sawBlepWeight_`, `invSawBlepWeight_`,
     `sawJumpResidual_`) — checked by brace-matching the block and walking the region's lower bound
     upward over contiguous lines that already name one of the six symbols, which is what pulls in
     the two weight bindings on the lines *above* the `if`;
  3. each of the six symbols has **exactly one declaration line tree-wide** (the definition
     predicate: the line ends with `{` and only specifiers/type precede the symbol, which is what
     excludes call sites like `if (sawWeight(c, n) > 0.0) {`).

Comments and string literals are blanked before counting (`code_only`), so a symbol named in prose
is not a hit — otherwise a comment could satisfy the table.

**Why declarations count as hits, and why that is the point.** The identity being protected is that
there is **one** definition and **one** reader per corrected symbol. A second definition in a
different file would be a second encoding free to drift; the counts table already includes each
declaration, so a name with `declared 1 / found 1` and a name with `declared 2 / found 1` are
distinguishable states and the second one fails. The gate reports the total it counted as
`ACCEPT-REPORT s6_wiring_call_sites=`, and the driver echoes the gate's verdict table on success,
so the number is **observable** rather than only asserted — but note *where* it is observable: CTest
runs the acceptance entry with `--output-on-failure`, which discards a **passing** test's output, so
a green CI run does **not** carry the table in its log. It carries it when the gate fails, and it is
committed for the passing case as `report/gh19-s6-saw-aa/evidence/acceptance_run.txt`, produced by
invoking the driver by hand with exactly the argv the CTest entry uses.

**Negative controls.** Four, each a separate way the check could be decorative: declared 2 / actual
1; declared 0 / actual 1; a row removed (⇒ an undeclared hit); a declared file made to vanish
(⇒ REFUSE `WIRING-SOURCE`). All four are exercised by hand, and the last two classes are also driven
by `wiring_control()` inside the mutant runner, which plants a real added call
(`wave_map::invSawWeight(c, n);`) into a copied tree and requires the gate to go RED **naming**
`S6-WIRING`. The pristine copy of the same tree must reproduce the reference verdict and must **not**
fire `S6-WIRING` — otherwise "the control fired" would only prove the check fires on everything.

## 5. The raw pin is inverted, not deleted

The `BASELINE-RAW-PIN` used to be load-bearing: the equality criterion read those bytes, so moving
one window fired the criterion. It is not load-bearing any more (§2), and the two ways to respond to
that are both wrong:

* **assert the old claim** — it is now false;
* **delete the check** — the demotion would then be untested, and the committed evidence would be
  unguarded.

So the check was **inverted**, and the criterion's real input was exercised in its place, both
through the **same** gate invocation so the difference is the input and not the harness:

* **§5 (inverted)** — with the pinned report and one committed baseline window moved, the gate must
  still **PASS**, no `FAIL-EQUALITY-SINE` / `FAIL-EQUALITY-ANTIPHASE` may appear, and the judged
  improvement columns must not move. That is the demotion, asserted.
* **§5b (new)** — the pipeline renders arm B fresh on every run; one ulp moved in **one window of arm
  B** must fire `FAIL-EQUALITY-SINE` with the improvement columns untouched. Arm B's window geometry
  is read from **arm B's own manifest** and required to agree with the baseline's, so the edit cannot
  be made at an offset outside the compared window.

The improvement-column half is what separates the surfaces: the improvement criteria read the
**report**, and the equality criteria read the **arms**, so a movement in one when the other was
tampered would mean the pins are not separating what this runner claims they separate.

## 7. What is NOT claimed

* **Not merged, not released, no MET.** PR #46 is **draft**; GH #19 / #15 / #12 stay open.
* The 12 pre-existing `--require-full` coverage gaps are **listed separately and unchanged**; the
  full-coverage gate was not touched. Any known by-design red in this PR's CI is **not covered by a
  standing approval** and needs approval **for this PR**.
* No anti-aliasing claim above `dt = kPolyblepMaxDt = 0.5` (the width is capped, the phase is not).
* The improvement columns are **output residual drops** against a fixed reference, not band gains;
  the fitted amplitude is reported separately and is never used to stand in for gain.
* The A/B proves the correction is **inert at the sine node** and that the wiring has the declared
  shape. It does not by itself prove the correction is *right* — that is the improvement columns'
  job, against the pinned baseline.
* `S6-WIRING` is a **structural** check: it constrains where the six symbols may be read. It cannot
  detect a defect *inside* the guard block.
* Local macOS/clang green is **not** MSVC green and **not** glibc green — §2 is exactly the lesson.
