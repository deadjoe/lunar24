# report/ — 阶段性分析报告

本目录存放对 Lunar 24 的**阶段性分析与审计报告**。

## 与其他目录的分工

| 目录 | 内容 | 谁写 |
|---|---|---|
| `design/` | 设计规范与计划（**是什么、要做成什么样**） | 设计线 |
| `design/00-status.md` | 滚动的实施状态与裁决流水账 | 工程总监 |
| `FINDINGS.md` | 测量记录与 provisional 常数台账 | 实施线 |
| `review/`（分支 `review/codex-*`） | 逐批次代码审查记录 | 审查线 |
| **`report/`** | **某一时点的整体分析/审计快照**（**现在处在哪、有什么问题**） | 外部或阶段性审计 |

`report/` 与 `review/` 的区别：`review/` 是**逐批次、面向单个改动**的审查；`report/` 是**跨阶段、面向整个项目状态**的快照，含独立复测与优先级建议。

## 命名约定

```
report/YYYY-MM-DD-<slug>.md
```

## 每份报告必须包含

1. **审计基线**：exact head commit、分支、工作树状态、当次门禁/CI 结果
2. **证据口径**：区分 `[实测]` / `[代码]` / `[手册]` / `[推断]`
3. **未验证范围的显式声明** —— 防止后续被当成已验证事实引用
4. **可复现方法**：探针源码或命令，且**必须实际验证过可原样运行**
5. **发现项与既有 GitHub issue 的对应关系**（哪些是新的、哪些已被跟踪）

报告一旦提交即为**该时点的快照，不做事后修订**；情况变化时另出新报告，不改旧文件。
